One token at a time

When you send a message, the model reads the whole context and produces a probability for every token in its vocabulary. One token is picked. It is added to the end of the text, and the whole process runs again to pick the next one. This loop continues until the model produces a special end token or hits a length limit. This is called autoregressive generation, and it is why chatbot replies appear word by word.

{{fig:genloop|The generation loop. The model predicts the next token, one is chosen, it is appended to the text, and the longer text goes back in.}}
In plain words

A language model never plans a whole answer and then types it out. It writes one token, then reads everything again, including what it just wrote, and writes the next. Any plan it has exists only in its internal numbers and in the text so far.

Choosing the next token: sampling

The model gives probabilities, not a decision. How a token is picked from them is called sampling, or the decoding strategy.

  • Greedy decoding always takes the single most likely token. It is predictable, but tends to be dull and can get stuck repeating itself.
  • Random sampling picks tokens in proportion to their probability: a 60% token is picked 60% of the time. This gives variety, and is why asking the same question twice gives different answers.

Temperature

Temperature adjusts how adventurous the sampling is. It reshapes the probabilities before picking. Low temperature (say 0.2) sharpens them, so the favourite almost always wins: focused, consistent, repetitive. High temperature (say 1.5) flattens them, so unlikely tokens get a real chance: creative, surprising, and more error-prone. Temperature 0 is the same as greedy.

{{fig:temperature|The same next-token probabilities at three temperatures. Low temperature makes the top choice dominate; high temperature spreads the chances out.}}
In your projects

Tiny Writer's “Creativity” slider is temperature. Try “Call me” at 0.2 and at 1.5 and compare.

Top-k and top-p

Even at normal temperature, thousands of very unlikely tokens together hold a little probability, and occasionally one is picked, sending the text off the rails. Two common filters cut off that tail first:

  • Top-k: only consider the k most likely tokens (say the top 40).
  • Top-p, or nucleus sampling: only consider the smallest set of top tokens whose probabilities add up to p (say 90%). When the model is confident, that might be two tokens; when it is unsure, two hundred.

Speed: prefill, decode and the KV cache

Generating a reply has two phases. First, prefill: the model reads your whole prompt in one go, which GPUs do efficiently because all tokens can be processed in parallel. Then decode: tokens come out one by one, each needing a pass through the entire model. Speed is quoted as tokens per second, and the delay before the first token appears is the time to first token.

Recomputing attention over the whole text for every new token would be wasteful, because the keys and values for earlier tokens never change. So the model saves them in memory as it goes. This saved store is the KV cache (key–value cache). Each new token only computes its own query, key and value, and looks up everyone else's.

Analogy

Writing a long essay and, before each new sentence, re-reading everything from the start. The KV cache is keeping index cards with the key points of each paragraph already written. You glance at the cards instead of re-reading the whole essay.

The KV cache costs memory, and it grows with the length of the conversation. For long contexts it can take more memory than the model weights themselves, which is one reason long context windows are expensive to serve (Chapter 15).

Good to know

Speculative decoding speeds things up with a helper: a small, fast model guesses the next several tokens, and the big model checks them all at once in one pass. Where the small model guessed right, several tokens are produced for the price of one big step. The output is identical to what the big model would have written alone.

Learning in the prompt

A trained model's weights are fixed, yet it can still pick up new tasks from the prompt alone. Show it three examples of turning English into pirate-speak, then give a fourth sentence, and it will continue the pattern. This is called in-context learning. Giving examples is few-shot prompting; asking with no examples is zero-shot. Nothing in the model changes; the examples only shape what the most likely continuation is. Writing prompts that get good results is called prompt engineering.

Thinking before answering

Since the model produces one token at a time, each token gets a fixed, limited amount of computation. A hard maths problem may need more thought than one step allows. The fix is to let the model write out its working: “first… then… so…”. Each written step becomes context for the next, so the model can build up a long chain of reasoning. Asking for this is called chain-of-thought prompting, and it measurably improves answers on hard problems.

Reasoning models (Chapter 10) are trained to do this automatically, often writing thousands of tokens of private working, sometimes shown to you as “thinking”, before the final answer. Spending more computation at answer time instead of training time is called test-time compute: a model allowed to think longer usually does better on hard problems, at the cost of time and money.

Analogy

Mental arithmetic versus pen and paper. Ask someone to multiply 47 × 38 instantly and they'll probably guess. Give them paper and a minute, and they'll get it right. The model's “paper” is the text it writes for itself.

Why models make things up

Language models sometimes state false things with complete confidence: invented quotes, fake references, wrong dates. This is called hallucination (or confabulation). It follows naturally from how they work. A model is trained to produce the most plausible continuation, and a plausible-sounding answer is not always a true one. When the model doesn't have the fact, the likeliest-looking text is still a confident sentence of the usual shape.

Analogy

A very confident student who hates saying “I don't know”. Asked about a book they haven't read, they produce a fluent summary built from the title, the author's other work and general knowledge. Parts are right, parts are invented, and it all sounds equally sure.

Post-training reduces this by rewarding models for saying when they are unsure, and tools like search (Chapter 13) let models check facts. It has not been eliminated. Check anything important.
