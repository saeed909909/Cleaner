The layers

Like the network inside a model, AI software is built in layers. Each one hides the complexity of the layer below.

{{fig:stack|The AI software stack, from the hardware up to the apps people use. Each layer builds on the ones below it.}}

Drivers and CUDA

At the bottom, the GPU driver lets the operating system talk to the graphics card. On top of it, NVIDIA's CUDA platform lets programs run general calculations on the GPU, not just graphics. Libraries such as cuBLAS (fast matrix maths) and cuDNN (fast neural-network operations) sit on CUDA. AMD's equivalent is ROCm; Apple's is Metal. A small piece of code that runs on the GPU is called a kernel (a different meaning from the CNN kernel in Chapter 6). Most people never write kernels; they use frameworks that already contain thousands.

Frameworks

A deep-learning framework gives you tensors, layers, automatic differentiation (backprop for free), optimisers, and GPU support, all from a friendly programming language.

  • PyTorch (from Meta, now run by the Linux Foundation) is by far the most popular, in research and industry alike. It is used from Python, the main programming language of AI.
  • JAX (from Google) is popular for very large-scale training, especially on TPUs.
  • TensorFlow (from Google) was dominant in the late 2010s. Its browser version, TensorFlow.js, is what runs Tiny Writer.
Analogy

CUDA is the engine and gearbox. PyTorch is the car's dashboard and pedals: you press “accelerate” and don't need to know how fuel injection works. Hugging Face, next, is a dealership full of ready-built cars you can drive away.

Model libraries and the hub

Hugging Face is the main public home for models and datasets, often described as the GitHub of AI. Its Transformers library can download and run thousands of models in a few lines of Python. Each model page has a model card: a description of what the model is, how it was trained, what it's for, its limitations, and its licence.

Inference engines and apps

Running a model efficiently, especially quantized and on modest hardware, is its own speciality:

  • llama.cpp: a fast C++ engine that runs GGUF models on CPUs, GPUs and Macs. Many home tools are built on it.
  • Ollama: a simple app and command-line tool for downloading and running models locally (“ollama run” and a model name).
  • LM Studio: a desktop app with a chat window and a model browser, also built for running models locally.
  • vLLM and similar servers: engines for serving models to many users at once in data centres, with tricks like batching many conversations together.
  • ONNX: a neutral model format and runtime, used to move models between frameworks and devices.

What is actually in a model download?

When you download a model, you typically get:

  • A configuration file: the architecture. Number of layers, embedding size, attention heads, vocabulary size, experts, and so on.
  • The tokenizer files: the vocabulary and merge rules.
  • The weights: one or more large files holding every parameter.

The weights come in a few formats. Safetensors is the modern standard: just numbers, safe to load. Older PyTorch files (.pt, .bin) use a Python format called pickle, which can contain hidden code that runs when the file is opened, so only load those from sources you trust. GGUF bundles config, tokenizer and quantized weights into a single file for llama.cpp-based tools.

Open, closed and in between

You'll hear models described by how available they are:

  • Closed (or proprietary) models, like the ones behind ChatGPT and Claude, can only be used through the company's apps or its API. The weights are never released.
  • Open-weight models, like Llama, Mistral, Qwen or DeepSeek, publish their weights for download, under a licence that may include conditions.
  • Open-source models, in the strict sense, also publish the training code and, ideally, the training data, so anyone could reproduce them. Fewer models meet that bar, and people argue about the term.

Using models over the internet: APIs

An API (application programming interface) lets a program send a prompt to a company's model over the internet and receive the reply. You authenticate with an API key (a secret password for your account, never to be shared) and are billed per token, usually with separate prices for input tokens and output tokens. Most AI apps you use are, behind the scenes, sending API requests.

Where people write the code

Most AI experimentation happens in Jupyter notebooks: documents mixing runnable Python code, results and charts. Google Colab offers notebooks in the browser with free access to a GPU for limited time, which is a good way to try things without any setup. For a long training run, like the 124M model, a plain Python script started from the command line and left running is more reliable.
