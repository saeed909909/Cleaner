What AI needs from a computer

Chapter 3 ended with a key fact: running a neural network is mostly matrix multiplication, the same simple multiply-and-add repeated billions of times. Each of those calculations is independent of the others, so they can all be done at the same time. AI hardware is designed around two needs:

  1. Lots of simple arithmetic in parallel.
  2. Moving huge amounts of data (the weights) to where the arithmetic happens, fast enough to keep it busy.

Keep both in mind; the second one matters more than most people expect.

CPU versus GPU

The CPU (central processing unit) is a computer's general-purpose brain. It has a small number of very powerful cores, typically 4 to 32 in a desktop, each able to handle complicated, branching tasks very quickly: running your operating system, a browser, a game's logic.

A GPU (graphics processing unit) was built to draw video games, which means calculating the colour of millions of pixels, each in the same simple way, sixty times a second. So it has thousands of small, simple cores that all do the same kind of operation at once. That turns out to be exactly what neural networks need.

{{fig:cpu_gpu|A CPU has a few large, clever cores. A GPU has thousands of small, simple ones. For one complicated task the CPU wins; for millions of identical small sums, the GPU wins by a huge margin.}}
Analogy

A CPU is a handful of brilliant professors. Give them a tricky, many-step problem and they'll solve it quickly. A GPU is a stadium full of thousands of school students who each know only basic arithmetic. Hand them ten thousand separate additions and the stadium finishes long before the professors do.

NVIDIA's GPU cores are called CUDA cores, after its programming platform. Since 2017, NVIDIA GPUs also contain tensor cores: specialised circuits that multiply small blocks of a matrix in one go, far faster than ordinary cores, especially with lower-precision numbers (Chapter 15). Most of a modern GPU's AI speed comes from its tensor cores.

Anatomy of a graphics card

{{fig:gpu_card|An NVIDIA RTX 2060 Super-style graphics card with its cooler removed, simplified. The GPU chip does the computing; the memory chips around it hold the model; the power circuitry feeds it; the slot connects it to the rest of the computer.}}
  • The GPU chip (the die) holds the cores, the tensor cores and a small amount of very fast on-chip memory called cache.
  • VRAM (video memory) is the set of memory chips around the GPU. The model's weights must live here to run fast. Your card has 8 GB of a type called GDDR6. Data-centre GPUs use HBM (high-bandwidth memory), stacked right beside the chip.
  • The power delivery (VRM) converts power from the supply; the power connector brings in extra power beyond what the slot provides.
  • The PCIe slot connects the card to the motherboard. Data moving between the computer's main memory and the card crosses here, and it is much slower than VRAM.

Memory: the real bottleneck

To produce each token, a language model must read every active weight from memory once. A 7-billion-parameter model stored at 2 bytes per weight is 14 GB of data, read for every single token. The arithmetic itself is quick; waiting for the data is what takes time. That is why, for running models, the most important number is often not computing speed but memory bandwidth: how many gigabytes per second the memory can deliver.

Analogy

A kitchen. The cooks (cores) are lightning fast, but every ingredient (weight) must come from the pantry (memory) through one doorway. However many cooks you hire, dinner can't come out faster than ingredients get through the door. Bandwidth is the width of the doorway. Memory capacity is the size of the pantry: whether the ingredients fit at all.

rough max tokens per second ≈ memory bandwidth ÷ size of active weights

Your RTX 2060 Super has 448 GB/s of bandwidth. A 7B model shrunk to 4 bits per weight is about 4 GB, so the ceiling is around 448 ÷ 4 ≈ 110 tokens per second; real software reaches perhaps half of that. This is also why MoE models (Chapter 12) are fast: only the active experts' weights are read for each token.

When a model doesn't fit in VRAM, parts of it can be kept in the computer's ordinary memory (system RAM) and moved across PCIe, or run on the CPU. It works, but it is many times slower, because those doorways are far narrower.

{{fig:memory_pyramid|The memory hierarchy. Near the top, memory is tiny but extremely fast; lower down it is huge but slow. Running a model well means keeping the weights as high up as they fit.}}

Other AI chips

  • TPUs (tensor processing units) are Google's own AI chips, built only for matrix maths and used in Google's data centres.
  • NPUs (neural processing units) are small AI engines built into phones and laptops, designed to run modest models using very little battery.
  • Apple silicon uses unified memory: the CPU and GPU share one large pool. A Mac with 64 GB can hold far bigger models than a graphics card with 8 GB, though with less bandwidth than a high-end GPU.
  • Other companies build AI accelerators too, including AMD's Instinct GPUs and various specialised start-up designs. Most AI software is written first for NVIDIA's CUDA, which has given NVIDIA a strong lead.

From one GPU to a supercomputer

A large model is far too big for one GPU, and training would take centuries on one anyway. So the work is spread across many. A typical AI server holds 8 GPUs connected by a very fast link (NVIDIA's NVLink); racks of servers are connected by high-speed networks such as InfiniBand; and a training cluster can contain tens of thousands of GPUs and draw as much power as a small town.

{{fig:datacenter|From chip to cluster. GPUs are grouped in servers, servers in racks, and racks into clusters, all wired together with fast networking so they can act as one machine.}}

Splitting the work: parallelism

There are several ways to divide a model across many GPUs, and big training runs combine them all:

  • Data parallelism: every GPU holds a full copy of the model and trains on a different slice of the data; afterwards they average their gradients.
  • Tensor parallelism: each layer's big weight tables are cut into pieces, with each GPU multiplying its piece.
  • Pipeline parallelism: different layers live on different GPUs, and batches flow through them like an assembly line.
  • Expert parallelism: in MoE models, different experts live on different GPUs.
{{fig:parallelism|Three ways to split work across GPUs. Data parallel: same model, different data. Tensor parallel: each layer cut into slices. Pipeline parallel: layers in stages.}}
Analogy

Making ten thousand sandwiches. Data parallelism: several identical kitchens each make their own share. Tensor parallelism: several cooks work on the same sandwich at once, one slicing, one buttering. Pipeline parallelism: an assembly line, where one station adds bread, the next adds filling, the next wraps. Big operations use all three at once.

All these GPUs must constantly exchange numbers, so the network between them is as important as the chips. The fastest training clusters are, in effect, giant single computers.
