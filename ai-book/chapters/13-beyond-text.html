Multimodal models

A modality is a kind of data: text, images, audio, video. A multimodal model handles more than one. The trick that makes this work is simple to state: turn everything into tokens. Once an image or a sound clip is chopped into pieces and each piece turned into an embedding, the transformer can process it alongside text with exactly the machinery from Chapter 9.

How models see: images as tokens

The vision transformer (ViT, 2020) cuts an image into a grid of small squares called patches, say 16 × 16 pixels each. Each patch is flattened into a list of numbers and turned into an embedding, just like a word token. A 224 × 224 photo becomes 196 “visual tokens”, and the transformer reads them like a sentence.

{{fig:patches|A vision transformer cuts an image into patches. Each patch becomes one token, so the image can be read by a transformer just like text.}}

To connect pictures with words, a model called CLIP (2021) was trained on hundreds of millions of images paired with their captions from the web. It learned to place an image and its matching caption at nearby points in a shared embedding space. That shared space is what lets you search photos with a sentence, and what lets chat models describe what is in a picture. A chat model that accepts images is usually called a vision-language model (VLM).

Analogy

Cutting a photo into jigsaw pieces and describing each piece in the same “language” the model uses for words. The model then reads the pieces like a paragraph, and attention lets each piece check the others to work out what the whole picture shows.

How models draw

Most image generators are diffusion models (Chapter 6) guided by text. Your prompt is turned into embeddings by a text encoder, and at every denoising step the diffusion network looks at those embeddings, through attention, to decide which way to clean up the noise. The text steers the sculpting.

Working on full-size images directly is slow, so most systems use latent diffusion: an autoencoder squeezes images into a much smaller latent form, the diffusion happens in that compact space, and the decoder expands the result back to full size at the end. Video generators extend this to stacks of frames that must stay consistent over time. Some newer systems generate images with transformers directly, token by token, like text.

How models hear and speak

Speech recognition (speech-to-text) turns audio into text. The sound is usually converted into a picture of its frequencies over time, called a spectrogram, which is then chopped into tokens and read by a transformer. OpenAI's open Whisper model (2022) made accurate, free speech recognition widely available. Text-to-speech runs the other way. Voice assistants now increasingly use models that take audio tokens in and produce audio tokens out directly, so they can respond quickly and keep tone of voice.

Giving models a library: retrieval

A model only knows what was in its training data, and that data stops at a knowledge cutoff date. It also doesn't know your company's documents or your personal notes. Retrieval-augmented generation (RAG) fixes this by looking things up first.

  1. Ahead of time, documents are split into chunks, and each chunk is turned into an embedding (Chapter 8) and stored in a vector database.
  2. When a question arrives, it is also turned into an embedding, and the database finds the chunks with the closest meaning. This is semantic search: it matches meaning, not exact words.
  3. Those chunks are pasted into the model's context window along with the question, and the model answers using them.
{{fig:rag|Retrieval-augmented generation. The question is used to find relevant passages, which are added to the prompt so the model can answer from them.}}
Analogy

An open-book exam. Instead of relying only on what they memorised, the student looks up the relevant pages, then writes the answer with the book open. They still need to understand the subject to find the right pages and use them well.

RAG reduces hallucination, keeps answers current, and lets a model cite its sources. Web search in chat products is a form of retrieval.

Giving models tools

A model can be told, in its system prompt, about tools it may use: a calculator, a web search, a calendar, a code runner. When it decides a tool would help, it writes a specially formatted request instead of a normal reply; the software around it runs the tool and pastes the result back into the context; and the model continues. This is called tool use or function calling.

Analogy

A clever person with a phone in their pocket. They don't need to do long division in their head or remember today's weather; they know when to pull out the calculator or check the forecast. The skill is knowing which tool to use, and when.

To avoid every app inventing its own way of connecting tools, standards have appeared. The Model Context Protocol (MCP), introduced by Anthropic in 2024 and since adopted widely, is a common plug for connecting models to tools and data sources: build a connector once and any compatible AI app can use it, a bit like USB for AI tools.

Agents

An AI agent is a model running in a loop with tools, working towards a goal over many steps: plan, act, look at the result, decide what to do next, repeat. A coding agent might read files, edit code, run the tests, read the errors, and fix them, dozens of times, before reporting back. A browsing agent might click through websites to book a table. When an agent operates a computer's screen, mouse and keyboard directly, it is called computer use.

{{fig:agent_loop|The agent loop. The model chooses an action, a tool carries it out, the result comes back as new context, and the model decides again, until the goal is reached.}}

Agents are powerful but bring new risks: they take real actions, mistakes can compound over many steps, and text they read along the way (a web page, an email) might contain instructions designed to trick them. That last risk, prompt injection, is covered in Chapter 18.

Memory

Models don't remember past conversations: each chat starts with an empty context window. Products that seem to remember you use the techniques above: saving notes about you somewhere and pasting the relevant ones into the context next time, or retrieving from past chats with RAG. The model's weights are not changing. This kind of memory is a feature of the software around the model, not of the model itself.

In plain words

Turn images, audio and video into tokens and a transformer can handle them all. Retrieval gives a model up-to-date facts to read; tools let it act and calculate; agents put it in a loop to finish multi-step jobs. The model in the middle is still a next-token predictor.
